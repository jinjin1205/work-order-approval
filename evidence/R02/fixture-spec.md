冻结日期：2026-10-26。执行者：Codex。全部为合成数据，不含客户数据。

依据：[统一验收样例](../../docs/验收样例.md)、[已确认决策 C03/C05](../../docs/决策与范围.md)。本文件固定输入和准备方法；[预期结果](expected-results.md)固定判据。产品公式仍以原 PRD/TRD 及已确认修订为准，不在项目里另建计算服务。

## 1. 样例隔离与最小初始化

候选核验采用独立空测试实例/站点/数据库，实例和数据库的确切创建命令由 R03～R05 按 R01 部署入口绑定。禁止在用户已有数据库上运行清理脚本。相同案例的每个分支从相同初始状态开始，不能接着上个分支剩余库存继续测。

1. 登记候选仓库 commit、框架/依赖版本、环境、时区、初始化方式、数据位置和实际创建时间。
2. 使用底座原生界面、导入或现有测试夹具建立下表数据；记录逻辑编号与底座真实 ID 的映射。此时不开发通用导入器、不猜测接口名称、不直写业务数据库绕过校验。
3. 按“单位→不良项→工序→路线→成品与原料→BOM→仓库及期初库存”顺序建立。角色与账号在业务操作前建立。期初库存用原生期初/调整单据，保留其来源。
4. 保存初始化后的清单或底座原生备份。只有备份实际恢复过才称“可恢复”；未恢复时仅记“初始化资料”。
5. 每个 CASE 独立建工单或独立重置测试实例，使用 `R02-<候选>-<CASE>-<分支>-<轮次>` 前缀。候选不允许某种编号时在映射表记录替代值。
6. 执行前核对库存、工单和关联事实初值；失败重试先查原请求/原单据，不能靠重新建一张单掩盖重复。

不能按上述方式建立某对象时记录具体阻碍；“缺入口/未找到”不是“功能不存在”。跨工单/权限测试另建对照单，不增加产品模块。

## 2. 基础输入

| 逻辑编号 | 输入 | 约束/来源 |
|---|---|---|
| U-PC | 件；数量允许6位小数 | 主链用整数，原料用0.5；单位精度来自TRD默认6位，不能在输入环节截成整数 |
| U-KG / U-G | 千克/克；换算1千克＝1000克；6位 | 仅 CASE-02 使用，不代表客户实际换算 |
| D-BURR / D-SCRATCH | 毛刺/划伤 | 不良项2个，供普通与AI草稿引用 |
| OP-10 / OP-20 / OP-30 | 下料/加工/检验；结构化加工类型均为“自制” | 顺序10/20/30；这是合成流程，不声称适配某行业 |
| RT-A-v1 | 上述3道有序工序 | CASE-07再改主路线版本，旧工单不受影响 |
| FG-A | 测试成品A，单位件，关联RT-A-v1 | 1种成品 |
| RM-A | 测试原料A，单位件 | BOM子项必须有可入库原料对象；不把“1种成品”误解为没有原料主数据 |
| BOM-A-v1 | FG-A父项基数1；RM-A用量0.5；损耗0 | 1行；不加按工序分批投料逻辑 |
| WH-R / WH-F | 原料仓/成品仓 | 主链 RM-A 初始20；FG-A 初始0 |
| WH-W | 在制仓，初始0 | 仅底座原生生产流要求时使用；是同一库存体系的位置，不建第二本账 |
| WO-BASE | FG-A计划10；3道任务每道计划10 | 独立新建；开始时有效报工/出入库事实均0 |
| 时间基准 | Asia/Shanghai，2026-10-20及次日 | 为样例日期，非真实生产记录；所有报工注明日期和秒 |

单位舍入样例：需求数量按 TRD 四舍五入至4位；输入与中间量保留十进制6位能力。对原料/良品数量超过配置精度的输入，不预填“通过”：核验底座是明确拒绝还是按显式单位舍入配置处理，并记录原值与结果；静默截断、取整、默认合法值均不通过。该项不借 R02 新定一套产品校验政策。

## 3. 最小角色与可见范围

以下是测试授权配置，不预设底座的角色名字或强制另建权限引擎。

| 测试账号 | 授权任务 | 必须拒绝的动作 |
|---|---|---|
| setup-admin | 配置样例、授权账号 | 不作为普通业务权限通过的唯一证据 |
| planner-a | 建单、生成明细、派工、授权的人工结束 | 普通操作不自动获得系统配置权 |
| worker-a / worker-b | 部门A；各自有权任务报工 | 未授予的工单改动、库存过账、他人数据查询/导出/AI读取 |
| warehouse-a | 授权仓库领退料、入库及其审批/过账动作 | 无授权仓库及跨工单错引用 |
| outsider-b | 部门B；仅对照工单可见 | 读取/报工/导出/AI访问部门A受限对象 |

任务授权分别建三个测试对象：ALL（被明确授权的登录操作工）、DEPT-A（部门A）、PERSON-A（仅worker-a）。ALL不是匿名访问。并发测试把 worker-a、worker-b 都授权给同一任务。每项拒绝先证明被测账号身份和权限，不以按钮隐藏为证据。
