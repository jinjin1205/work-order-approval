# Design

## Context

真实入口、输入和许可复用沿[原R07本包绑定](../../../evidence/R07/card-binding.md#2026-10-29-b05b06b07空明细与人工确认生成绑定)。原25份累计源码/e15fba已与保留测试容器33项清单核对，不重建环境。

## Goals / Non-Goals

**Goals:** 实施原卡的空明细/确认生成子项，继续同一权威BOM展开和审批规则。

**Non-Goals:** 本包以外状态、任务编辑、完整结构锁/库存并发、AI、手机及交付。

## Decisions

不增加通用表或元数据。用原算法构造内存计划并计算来源/输出指纹，预览不保存；确认先锁父工单并重读，比较来源和版本后用原save事务生成。相同现有计划直接返回，不二次save；已有不同计划拒绝覆盖。新流程只针对审批工单，原非审批生成方式保持。中文按钮要求先保存再预览。

## Risks / Trade-offs

旧helper主动准备明细仍属显式内部调用，不能以新流程改坏原fixture/旧单。原BOM/工单保存受影响回归按差异选择，不跑全部上游依赖。有限幂等/父锁不证明完整G3；事务故障测试、真实页面和现场验收分开。
