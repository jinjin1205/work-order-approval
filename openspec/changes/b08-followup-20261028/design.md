# Design

## Context

当前只引用[原R07不同请求并发绑定](../../../evidence/R07/report-concurrency.md#2026-10-28-不同请求并发余量续接绑定)，沿B08-04/B09的I03/I04验证既有确认入口；两场景各一次有限HTTP通过，4次确认3成功/1预期拒绝且未重放，公开保存仍待核，本包未收口。未出现产品失败，原控制器/测试均未改；不改Frappe、不新增API/产品权限，不顺带关闭完整G3。历史旁路、单价/效率等已收口子包不重开。

动机和范围见[proposal.md](proposal.md)。当前做/不做/通过条件与两行验收只由[原卡不同请求并发子节](../../../docs/任务卡/02-生产与物料闭环.md#2026-10-28-不同请求并发余量续接)及R07规定；不复制方案或清单。

## Goals / Non-Goals

**Goals:** 保持原卡为唯一验收与进度来源，用 OpenSpec 聚合其入口和本批证据。

**Non-Goals:** 不新建权限/计算框架、平行清单或独立工作树；不把工具规划状态当业务通过。

## Decisions

- 复用`.development/repos/erpnext`的`codex/xgd-maintenance`工作副本，保留累计25份源码；本包维护25份和33份运行清单已核，累计e15fba补丁不变；无源码变化，未build或重启。新工作树不会自动带入累计补丁，故继续既有checkout，不用上一包核对冒充本包验证。
- 复用原HTTP/barrier/保存模式，使用本包2用户/Employee、2审批单和2隔离工作站。两身份授权/预览、独立连接/不同键、请求区间重叠和独立回读已核，旧20表原行/捕获列保留；实际脚本/CLI与结果只在原卡/R07维护。记录Barrier(2)方式和请求时刻，未单独采集释放事件或DB锁轨迹；hour_rate=0不外推非零成本，HTTP不冒充压力、页面或单测。一次脚本定向审查在执行前补断言，未产生产品失败。
- 使用默认 `spec-driven` 与 `skip_specs: true`：本次没有新增或改写需求，故引用已有契约；`tasks.md` 也只引用原卡。接受 CLI 不解析外部复选框的限制，不另建自定义 schema 或重复任务以凑齐状态。

## Risks / Trade-offs

- [CLI 规划文件状态可能被误读为实现完成] → 原卡和本批实际证据权威；不归档未完成包，不用 CLI 状态增加完成数。
- [历史样例已消耗、旧证据有限] → 不重放旧 HTTP 批，不把受控测试/页面/现场或完整 G1/G2/G3 混为一谈；按原卡保留停止和交付边界。
