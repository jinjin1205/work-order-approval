# 工厂生产工单审批与执行

这是开发归档，**不是已可交付的产品**。客户自行部署、简体中文、PC＋手机网页、首版三项AI建议/草稿及人工确认要求不变。首版只做生产工单；维修、检修、委外后续另定。工单执行前审批与“报工确认即生效、无额外主管审批”分开。

## 代码保存方式

[source/source-lock.json](source/source-lock.json)固定ERPNext v15.124.1的完整上游提交。`source/erpnext/`保存截至本批的**20个完整修改或新增文件**及上游许可证；[当前差异补丁](evidence/B14/implementation.patch)同时保留。Frappe v15.124.0保持原版，没有重复上传完整上游目录、Git缓存或容器镜像。本轮增量为两个原生时段配置DocType、公司和父子表写权限、内部读取及四条CSV中文翻译；复用既有计算，未新增服务或生产/库存账本。

在一份新克隆中准备完整维护源码（需要Git、Python 3、网络；不启动数据库或写业务数据）：

```sh
python3 tools/prepare_source.py
```

脚本固定获取上游SHA，核对原文件哈希，再覆盖清单中的20个已保存文件（含8个新增文件；上游应不存在）并验证修改后哈希。已有`.development/repos/erpnext`时会停止，不覆盖已有工作。新增BOM字段已在隔离测试站和既有开发站执行原生reload-doc，数量默认精度使用六位；既有站运行新源码前须先按所属任务导入元数据并验证，不能直接启动新镜像而沿用旧字段。B14两份新DocType须先按[evidence/R07/time-config-binding.md](evidence/R07/time-config-binding.md)加载子表再主表；`.development/checks/b14_prepare.py`只准备隔离站角色/link-select，客户配置角色及Company授权需显式映射。随后按[本地开发环境说明](.development/README.md)配置本机新凭据和独立站点。镜像是已验证的固定ARM64基线，其他机器、完整生产服务及客户部署仍需对应验收。

## 公开与本地边界

- 公开：完整修改源码、测试定义、版本与许可证、任务卡、脱敏方法/结论、可复现脚本、结果摘要和文件哈希。
- 不公开：任何实际凭据、`.env`、私密配置、站点/数据库/卷、实际运行生成的测试单据、原始HTTP响应、运行日志、截图、缓存。本地原件保留。
- 测试定义和预期示例用于复现，不是本地运行数据导出。[证据索引](publication/evidence-index.json)说明哪些原件仅本地保留；[转换记录](publication/export-transformations.json)记录公开副本处理。
- `publication/files.sha256.json`覆盖本次公开内容。完整性指该明确范围全部提交并远程回读一致，不表示上传了被排除的私密/运行数据，也不表示产品全功能通过。
