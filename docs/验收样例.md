# 统一验收样例

日期：2026-10-26。以下全部是合成输入与预期结果，不是已运行结果。适用于候选对照和后续任务卡，避免为每个底座另设一套“容易过”的标准。

R02已冻结[v1输入与初始化](../evidence/R02/fixture-spec.md)和[详细步骤/预期](../evidence/R02/expected-results.md)，独立算术核对36项一致。随后R05已执行部分候选路径，成功子项、失败和未验证见[运行记录](../evidence/R05/run-record.md)。下列完整判据保留未勾选：部分运行和样例冻结均不能代替整项验收通过。

执行前由 R02 固定样例、单位、业务状态与输入来源。候选核验的真实命令／界面步骤在 R03～R05 根据已读部署资料绑定；选型后 B/A/Z 实施卡的步骤由 R07 绑定。相关实现、输入或依赖变化才重跑受影响项。待决策的样例只能核现状，不能标为最终需求通过。

每张卡只验收其负责的样例子项；没有依赖尚未形成的页面、库存、导出或AI结果就不等待这些结果。B17 合并核心链证据，A01～A03 合并首版AI证据，Z02完成首版收口。后续联调只补新形成或变化的路径，不重复已完成的独立检查。

证据统一放 `evidence/<任务ID>/`：记录版本、环境、输入、步骤、实际值、预期值、结果与限制。截图可辅助，不代替可核对的记录和单据。结果使用“通过／失败／未验证／不适用（原因）”，不能把缺数据写成0。

**C08中文验收补充（R07）：**首版PC/手机网页、业务提示、必要报表和导出列名使用简体中文。沿用底座翻译；登录账号语言、上海时区和CNY配置需回读及页面验证。原始单号/型号/代码标识不翻译，不新增英文版本；不以设置了zh证明所有业务页已中文。具体入口见[中文绑定](../evidence/R07/chinese-interface.md)。

## CASE-01 一张工单的完整关系

**前置：**合成单位“件”、不良项2个、工序3道、路线1条、产品1个、BOM1行，父项基数1、单位用量0.5、损耗0；工单计划10件。原料仓可用量20，成品仓初始0。每道任务计划10。

- [ ] 建工单后任务0、用料0，界面提示下一步；产品缺路线／BOM时提示具体缺项。
- [ ] 人确认生成后为3个有序任务和1行用料，需求5；重复确认不生成重复明细。底座原有自动生成默认行为若不符，记录最小配置／改造差异。
- [ ] 领料单生效5后，发料来源仓数量变15，本单累计领料5；如底座用在制仓转移，记录对应库存位置及去向，不把转移误称消耗。
- [ ] 三道工序各报良品10，查看任务完成比例从1/3到3/3；整单合格成品不因三道工序各10而被加成30。
- [ ] 成品入库10后成品仓10；工序报工和入库记录分别可查，不能重复入库。材料在发料和完工时不被重复扣同一笔。
- [ ] 每笔报工、用料、出入库均可反查工单、来源行、操作者、时间及有效状态。

**失败：**无路线、无BOM、同编号重复、已取消工单提交、重复生成、引用不存在或无权限对象均不产生半张有效业务单。

## CASE-02 小数、单位、用量与库存成本

所有精度以 TRD 的十进制原则为目标；不能仅看界面小数位。换算系数使用明确的合成值，不引用未确认的客户单位。

| 输入 | 预期 |
|---|---|
| 计划100，用量0.5495，基数1，损耗0 | 需求54.9500（允许界面省略末尾0） |
| 计划100，用量0.083333，基数1，损耗0 | 需求8.3333，不得取整为9 |
| 计划100，用量0.5，基数2，损耗10% | 需求27.5000 |
| 计划100，用量0.000167，基数1，损耗0 | 需求0.0167 |
| 1千克换1000克；领0.001千克、退0.0004千克 | 净领0.0006千克＝0.6克，存储及换算不得提前取整 |
| 父项基数0、负数量、无效单位换算、超过单位允许精度 | 拒绝或按已明确舍入规则处理；不得静默修成默认合法值 |

- [ ] 计算、中间值、存储、显示、报表／导出、AI取数核对同一规则，不新增第二份公式。
- [ ] 有库存估价时核原有移动加权平均：入10单位单价2，再入10单位单价4，无其他费用，结存20／价值60／均价3；出5后余15／价值45。退料估价依据原单或既有一致规则核实，不自行发明另一套估价。
- [ ] 计划8良品＋2不良时任务完成比例可到100%，良品率80%，合格交付数量仍为8，不显示已交付10。
- [ ] 另有返工3时良品率仍80%；良品与不良均0时显示“—”；工单无任务时完成比例显示“—”，不记已完成。

## CASE-03 工时与边界

| 输入 | 预期 |
|---|---|
| 09:00–17:00；休息12:00–13:00；停工0、加班0 | 报工28800秒、休息3600秒、有效25200秒 |
| 22:00–次日02:00；休息23:00–01:00；无其他项 | 报工14400秒、休息7200秒、有效7200秒 |
| 09:00–17:00、休息1小时、停工8小时 | 拒绝，提示允许停工最多7小时 |
| 报工完整落在休息内、无停工加班 | 有效工时0；效率显示“—”。不是必然负数，不能照搬旧T-018的错误预期 |
| 有效工时2小时、单价10／小时 | 预计工资20；仅预计数，不扩成工资结算模块 |

- [ ] 结束早于开始、加班超过已定额度、伪造客户端有效工时、交叠休息段重复扣减均有确定行为；客户端派生数字不作为事实来源。
- [ ] 跨天按明确时区计算。没有时段规则不能默认为有休息；规则缺失按确认的默认值展示，不能掩盖配置错误。

## CASE-04 重复、并发与失败恢复

- [ ] 同一有效报工请求重复提交2次：只有一笔有效报工、一次数量增量，返回可识别的原结果。
- [ ] 同一库存单重复过账：扣库、回写只发生一次。
- [ ] 同一任务剩2，两名有权人员并发各报2：有效合计不超过2，失败方看到当前余量／冲突原因，不返回假成功。
- [ ] 两个不同有效请求各报1：都可成功，不能被过度去重吞掉第二笔。
- [ ] 服务端成功但客户端超时后重试：可找回首次结果；服务端失败时无部分计数或孤立单据。

本卡验证业务去重，不把事务、行锁或前端按钮置灰直接当作证明。不规定无依据的100并发性能目标。

## CASE-05 冲销与更正

**输入：**任务计划10，原有效报工良品10；在没有后续不可逆业务的受控场景中更正为良品8。

- [ ] 原记录内容保留，关联冲销／更正记录、原因、人员、时间可查；有效净良品8、余量2。
- [ ] 根据底座选择一条可验证的冲销路径，不为了保险同时造全冲销与部分冲销两套机制。
- [ ] 原记录不能通过普通编辑、删除、批量接口或删除父任务／工单被抹除。
- [ ] 重复冲销不产生第二次回退；冲销不超过原有效数量。
- [ ] 状态、进度、预计工资及确有联动的物料／库存按同一规则核对。已有下游记录阻止直接更正时，给出具体依赖与处理顺序，不静默破坏下游。

## CASE-06 领、退、耗的区别

**输入：**来源仓20，本单需求10；领10、退2，均已生效。

- [ ] 来源仓12；累计领10、累计退2、净领8。若使用线边仓，位置记录也必须一致。
- [ ] 需求10时累计领料进度100%；净领8另列，不能让同名指标一会儿累计一会儿净额。
- [ ] 另有待审批领料3，不加入已领、净领和库存过账量。
- [ ] 没有实耗记录时标“实耗未记录／未验证”；不得自动填实耗8。若仅按BOM推算，标“理论用料”及依据。
- [ ] 实耗记录明确为7时，净领与实耗差1；原因未知时只列待核对的在制余料／遗漏记录等可能项，不能断言丢失。
- [ ] 超库存领料、超可退范围退料、跨工单错引用被拒；已领／已退后结构锁有效，即使净额归零也不得据此删除历史关联。

## CASE-07 权限、状态、路线与事实生效

- [ ] 合法角色能做授权操作；无权用户即使直接请求接口也被拒，不能只隐藏按钮。
- [ ] 所有人／部门／个人的任务报工权限分别验证；不同可见范围不能越权查询、导出或通过AI取得数据。
- [ ] AI草稿不改变数量；人确认报工后立即生效，无额外主管报工审批；库存仍按其审批／过账状态统计。
- [ ] 首条有效报工自动开工；任务良品8＋不良2达到计划10可完成，但合格交付仍不足10；人工结束保留差额与原因。
- [ ] 修改主路线后旧工单路线与历史报工可追溯；新工单按当前有效路线创建。
- [ ] 已结束／取消等不允许的操作拒绝；复制工单不复制有效报工和库存事实。

## CASE-08 手机与弱网

- [ ] 普通岗位重新登录后，核心操作及无权限/超量/冲突/重试结果提示保持简体中文；桌面小屏和真机证据分别记录。
- [ ] 计划员／工人／仓管按角色从手机网页完成任务定位、扫码、报工、领退料所需操作。
- [ ] 常用上下文和默认值正确，异常数量／不良才要求必要补充；记录实际点击、输入与完成时间，不预填“无需培训”。
- [ ] 网络中断、提交后无响应、刷新与再次提交：显示明确的未提交／处理中／成功／失败状态，重试不重复入账。
- [ ] 扫错码、无权限码、摄像头不可用有可操作提示，必要人工定位入口保留。语音识别与录音失败归 CASE-09/A03，不阻塞本样例的核心手机验收。
- [ ] 弱网恢复不等于承诺完整离线。目标手机、浏览器、扫码／录音权限条件记录在证据中。

## CASE-09 首版 AI 建议与草稿

**输入：**本轮合成工单与路线/BOM；文本及语音“这批出了8个好，2个毛刺”。

- [ ] AI-1 给出将生成的任务与用料预览，数量来自系统计算；忽略建议不生成明细；人确认后与普通业务入口一致。
- [ ] AI-2 只给有依据的候选字段。没有历史样例时说明无足够依据，不能编“同类12单”。
- [ ] AI-3 将8良品、2不良及匹配不良项放入草稿；识别含混时要求确认，不把缺失工时／人员默认为真实记录。
- [ ] 人可检查和修改草稿；取消无事实入账；确认后按当前权限、余量与状态检查，重复确认不重记。
- [ ] 恶意文本要求绕过权限、直接扣库或改他人工单时不执行。草稿携带的对象ID和计算结果都不能绕过后端边界。
- [ ] 使用真实配置的模型和语音服务验证；模拟返回只记“受控模拟通过”。记录模型版本、请求结果、时延和可获得的费用数据；未知费用标未知，不写0。
- [ ] 录音权限拒绝、语音服务不可用或识别失败时提供明确提示及文本／人工入口；不能把人工成功显示为语音或AI成功。

## CASE-10 后续 AI 问答与差异

首版AI三项不以本样例作为额外问答交付要求；A04/A05激活后执行。

- [ ] “今天做了多少”：区分工序产量和成品入库量，附时间范围、统计状态和可访问的单据来源。
- [ ] “哪些单可能逾期”：有交期与当前状态则如实列；没有可靠工时／产能时不编确定的预计完工日。
- [ ] “料为什么少3件”：只陈述有证据的差异；缺实耗、在制余料或记录矛盾时明确不能确定原因。
- [ ] 无出处数字、过期数据、无权单据、含提示注入的备注、模型或工具失败均有边界；不无限重试、不把空结果当零。

## CASE-12 真实现场试点

- [ ] 启动前取得行业与产品场景、岗位验收人、可用数据范围、目标设备、试点时间；未取得就标现场未验证。
- [ ] 计划员、操作工、仓管分别完成选定样例及现场任务，记录独立完成／需要协助／失败的位置和原因。
- [ ] 依据试点实际任务记录应报与已报，不用“每单有一条”替代完整性；数值阈值、参与人数与试点窗口由业务验收人确认，不捏造。
- [ ] 原资料提出一周观察；实际观察日期和每日记录如实保留。短时模拟、压缩时间或补写日志不能冒充一周。
- [ ] 核对报工、领退料、成品入库、冲销、AI草稿确认及权限；签收或问题清单标明具体版本、范围和未通过项。
