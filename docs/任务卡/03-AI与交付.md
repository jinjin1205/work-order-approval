## A01 · AI 取数、草稿与确认边界

**状态与门槛：**首版条件卡；依赖B02已验授权规则、B04权威计算、B16所需取数/来源证据、R07本卡绑定、C02、C03。C06的模型／语音服务、联网、费用和数据发送条件需在真实调用前补齐。可以先定义结构和用合成数据验证边界，不冒充真实模型结果；AI具体接入由本卡验，不作为B02反向前置。

**目标：**AI 只能读取授权且有来源的数据并生成建议；人确认后进入原业务路径，避免另造一套写入与计算逻辑。

**复用与允许范围：**检查底座已有插件、API、鉴权、审计、草稿和确认机制；只补缺失连接。禁止新造通用智能体平台、多模型路由、自治执行器或独立事实库。

- [ ] 绑定每个工具的实际输入／输出和权限；草稿带建议内容、依据、对象引用及必要版本信息，计算值来自 B04。
- [ ] 人工确认使用正常业务入口；对象、状态、数量、权限在确认时有变化就重新核验，未变化的内部数据不重复堆检查。涉及执行时消费B19绑定的工单审批门槛；AI不自行审核、签批或绕过门槛。
- [ ] 沿用审计记录关联模型输入范围、草稿、确认人和最终单据；限制敏感数据与密钥记录。
- [ ] 统一处理工具／模型失败、权限拒绝、无数据和输出格式错误；给出真实失败原因，不无限重试或返回假建议。
- [ ] 执行 CASE-09 的越权、注入、过期草稿、取消、重复确认场景；对同一写入入口不复制第二套业务校验。

**验收：**AI 身份不能直接写正式报工、改工单状态或扣库；人确认的写入仍遵守 B09 防重及 B02 权限；模拟与真实调用证据分开。

**证据／结束：**`evidence/A01/` 保存工具映射、权限及边界验证；绑定并验证当前三项能力的必要边界即关闭。其他 Agent 编排不追加。

## A02 · 明细建议与字段补全（AI-1／AI-2）

**状态与门槛：**首版条件卡；依赖 A01、B05、B06、B07、B14、R07。真实模型验证依赖可用配置；确定性预览无需强制调用模型。

**目标：**建单后明确下一步并减少重复填写，同时保留人的选择。

**复用与范围：**用现有路线／BOM展开与字段配置提供预览和候选；不新增主数据推荐平台、不复制任务或需求量算法。保留普通手工入口。

- [ ] 生成任务数量、步骤和用料数量预览，引用具体路线／BOM及其版本；建单本身仍不生成事实明细。
- [ ] 人确认后复用 B06／B07；忽略建议没有业务副作用，重复确认不会生成重复任务或用料。
- [ ] 对必填缺失字段给出可解释候选；历史样本存在才引用实际数量，样本不足明确说明，不虚构“相似工单”。
- [ ] 用户可选择、修改或拒绝建议；缺少路线、BOM、可用候选及上下文冲突时显示具体缺项。
- [ ] 核验 CASE-09；记录实际返回时延和正确性。原 PRD 的建单建议2秒目标按真实环境测量，不能在未测时宣称达标。

**验收：**预览与确认后结果一致；路线变化后旧预览不能悄悄生成错误任务；字段建议具备可核对依据，失败时不阻断可用的普通业务操作。

**证据／结束：**`evidence/A02/` 记录输入、预览、确认结果、失败和时延；当前 AI-1/2 样例通过即关闭，不追加后续预测能力。

## A03 · 语音／文本报工草稿（AI-3）

**状态与门槛：**首版条件卡；依赖 A01、B08、B09、B13、R07。语音服务／模型配置、发送数据范围及额度属于 C06 局部前置；未取得时语音真实能力标未验证，不关闭整张卡。

**目标：**让现场人员把一句话转成可检查的报工草稿，并由本人确认生效。

**复用与范围：**优先现成文本输入、录音、语音识别及报工表单；复用 B08/B09 确认写入。只实现当前报工字段，不做语音助手控制整厂。

- [ ] 从选定工单、任务和当前用户建立上下文；文本／语音识别结果转成草稿，缺失或冲突字段提示本人确认。
- [ ] 展示识别文本、良品／不良、原因、工时等本次拟提交内容；金额与有效工时仍由确定性规则计算。
- [ ] 允许编辑草稿、取消或确认；通过B19工单执行前审批条件和原业务校验后，正式记录确认即生效，无额外主管报工审批。不得把草稿确认当成工单签批，也不得提前累加正式产量。
- [ ] 对录音被拒、噪声误识别、服务超时、型号配置错误、库存或任务状态变化、重复确认逐项验证；人工输入入口保留且明确不是语音成功。
- [ ] CASE-09 的“8个好、2个毛刺”文本及真实语音各运行；关键数量识别不确定时要求核对，不能猜成确定事实。

**验收：**取消无入账；确认一笔且可追溯；数量变动后按当前状态处理；真实语音和模型调用有证据。记录实际点击与耗时，受控通过不等于工人无需培训。

**证据／结束：**`evidence/A03/` 保存获准的合成输入、草稿、确认单据与失败结果。语音、文本和确认边界均通过方可关闭；不将后续数据问答加入首版。

## A04 · 发料建议与差异解释（AI-4／AI-5）

**状态与门槛：**后续阶段条件卡；依赖 A01、B10、B11、B12、B16、R07，且阶段已激活。首版不因本卡未完成受阻。

**目标：**给仓管提供有数量依据的发料建议，给负责人解释已知差异并指出缺失证据。

**复用与范围：**沿用库存可用量、原领退单、BOM、工单需求和真实消耗记录。禁止把发料建议公式与采购缺口公式混用；不新增MRP、采购系统或未经请求的消耗采集系统。

- [ ] 固化发料建议与差异的输入定义、计算入口、单据状态和公式；明确净领料、在制余料、理论耗料和实耗。原“需求－库存－在途”不能直接命名为建议发料量。
- [ ] 根据已确认公式提供建议与依据，人确认实际出库；建议与实发的差异可查，不自动扣库。
- [ ] 系统计算差额，AI只组织解释；没有实耗记录时明确无法确认实耗或原因，不填0或用BOM冒充。
- [ ] 核验 CASE-06、CASE-10 的缺记录、相互冲突、跨单位与过期状态；结论区分事实、可能原因、待查项。

**验收：**每个数可回算并追到单据；实际原因不能由一个差值推出；没有足够数据时给出缺口仍属于正确响应，不承诺必能归因。

**证据／结束：**`evidence/A04/` 保存公式与来源、正常和缺证据样例；确认范围通过即关闭。公式或实耗定义仍有歧义时只阻塞本卡，不重写整个系统。

## A05 · 有来源的数据问答（AI-6）

**状态与门槛：**后续阶段条件卡；依赖 A01、A04、B16、R07，且阶段已激活。

**目标：**回答已确认的产量、交期风险、物料差异问题，并能回到原始证据。

**复用与范围：**调用授权查询与计算结果，不让大模型自由写SQL或自行汇总事实；不开发通用BI、任意问题知识库或自主行动系统。

- [ ] 按 CASE-10 的三类问题绑定真实查询；回答包含时间范围、统计状态、公式含义和单据入口。
- [ ] 每个业务数字对应来源；生成的无来源数字拒绝展示，按确定策略提示失败／缺资料，避免无上限重答。
- [ ] 无可靠工时／产能输入时不输出确定完工日；不把任务完成比例当交付概率。
- [ ] 验证越权问题、无数据、矛盾记录、备注注入、工具不可用、过期结果与导出权限一致性。

**验收：**CASE-10 三类问题与失败路径通过；缺证据时回答边界正确；可靠性说明来自样本和缺口，不虚构分数或“高／中／低”阈值。

**证据／结束：**`evidence/A05/` 留问题、工具结果、回答、出处与限制。当前问题集通过即可，不自动扩成开放域助手。

**目标：**另一位实施人员能用固定版本和说明，在目标条件相符的环境完成部署与恢复。

**复用与范围：**沿用底座现成部署、迁移、备份、日志和恢复流程；必要时补具体配置，不从零再造运维平台。保留所需源码、版权声明、许可证和第三方清单。

- [ ] 冻结版本与配置示例，列出系统、依赖、端口、数据目录、模型／语音服务、密钥输入方式和已知限制。

- [ ] 验证备份、恢复及失败时恢复路径；合成工单、冲销、库存与必要附件恢复后可核对。
- [ ] 根据 R01 形成实际交付源码与许可资料清单；未确认的私有依赖不得悄悄混入交付。

**验收：**CASE-11 通过，交付版本与已测版本一致；错误配置、依赖不可用、恢复失败均明确报告，不以本机能启动替代客户部署。

**证据／结束：**`evidence/Z01/` 保存部署记录、恢复核对和交付目录索引。受控交付包可单独验收，正式客户上线状态另列。
